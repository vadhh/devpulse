# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

DevPulse is a [Pock](https://pock.app) widget (macOS Touch Bar) that shows CPU, memory, and battery, each as an SF Symbol icon, a dot-matrix history graph (10 samples × 5 dots) and a percentage. It is Swift/AppKit, built as a `.pock` bundle against PockKit (pulled as an SPM package from `pock/pockkit` `master`).

## Build

```bash
./build.sh
```

This runs `swift build -c release` using `Package.swift`, and needs only the Command Line Tools, not Xcode, because the latest Xcode won't install on this Mac. The script turns `.build/release/libDevPulse.dylib` into `build/DevPulse.pock/Contents/MacOS/DevPulse`, signs it ad-hoc, and copies it to `~/Library/Application Support/Pock/Widgets/`. It then **kills and relaunches Pock**.

- `DevPulse/Info.plist` uses literal values, with no `$(...)` placeholders, because nothing fills them in. `NSPrincipalClass` must resolve to `DevPulseWidget`.
- PockKit (and TinyConstraints) are linked statically into the widget. That works because `PKWidget` is an `@objc` protocol, and Pock matches it by name.
- Build only: `swift build -c release`. Typecheck only the logic that doesn't use PockKit: `swiftc -typecheck DevPulse/Sources/DevPulseMonitor.swift`.
- `project.yml` is the old XcodeGen/Xcode setup and isn't used anymore.
- The `com.st4rdhoom.devpulse` defaults domain holds the user's live widget settings, and the running Pock reads it. Don't write or `defaults delete` it while testing.
- Don't create fonts or measure text inside `draw(_:)` or the width functions. `DevPulseView.text` caches the font and value width per text size. Creating them on every call at animation frame rates crashed Pock inside CoreText (`NSInvalidArgumentException: attempt to insert nil object` from `sizeWithAttributes:`). Crash reports are in `~/Library/Logs/DiagnosticReports/Pock-*.ips`.
- Keep animation frames cheap; they run at 20fps inside Pock. The timer calls `invalidateAnimatingGraphs()`, which invalidates only the graph rects of meters that move, and `draw` skips meters outside the dirty rect. Icons are rendered once into cached Retina bitmaps (`icons`). Dynamic colours are resolved to sRGB once per meter or column, never blended per dot. Full-view redraws at 20fps kept Pock at ~35% CPU; measure with `top -pid $(pgrep -x Pock)` and `sample Pock 5`.
- There are no tests or linters. To verify a change, install it and look at the Touch Bar. Tapping the widget forces a refresh.

## Architecture

`DevPulseWidget` asks `DevPulseMonitor` for a `DevPulseSnapshot`, and `DevPulseView` draws it.

- **`DevPulseWidget`**: the Pock entry point (`PKWidget`). `NSPrincipalClass` in `Info.plist` points at it. It owns lifecycle only. It polls every 3s, and only while visible (`viewWillAppear`/`viewDidDisappear`). A `refreshInFlight` flag drops overlapping refreshes.
- **`DevPulseMonitor`**: samples on a private `.utility` queue and sends the result back to main through the widget. Readings come only from native APIs, never from spawned processes (`top`, `vm_stat`, `pmset`):
  - CPU: `host_statistics(HOST_CPU_LOAD_INFO)`. It reports the share of non-idle ticks since the previous sample, so the monitor keeps `previousTicks`, which is only touched on its queue. The first sample returns `nil`.
  - Memory: `host_statistics64(HOST_VM_INFO64)`, using Activity Monitor's "Memory Used": internal − purgeable + wired + compressed pages, over physical RAM.
  - Memory pressure: `sysctlbyname("kern.memorystatus_vm_pressure_level")` (1 normal, 2 warning, 4 critical), mapped to `MemoryPressure`.
  - Battery: IOKit `IOPSCopyPowerSourcesInfo`. `onAC` means plugged in, and `charging` (`kIOPSIsChargingKey`) means actually gaining charge.
  - A `nil` reading renders as `—`.
- **`DevPulseView`**: draws everything itself in `draw(_:)`, with no subviews. It keeps the last 40 values of each reading (`cpuHistory` etc.), the longest selectable history, and draws the last `Preferences.historyLength` of them, and `apply` adds one sample and marks the view for redraw. The grid geometry is a `Graph` value rebuilt from `Preferences` on each draw. Spacing between dots is `dot + max(1, 0.4·dot)`, snapped to half points so dots fall on whole Retina pixels. "Full height" (`rows == Preferences.fullRows`, which is 0) uses as many rows as fit in 30pt minus `verticalMargin`, and explicit row counts are clamped to that. Each column lights `value/100 × rows` dots, rounded to the nearest, with at least 1 dot for any non-zero value. The column's colour comes from `loadColor`/`batteryColor` for that sample. The width comes from the number of visible meters and the history length; `preferredWidth` (about 290pt at the defaults) is only the initial frame. SF Symbols are painted grey by hand, because symbol images ignore the fill colour. Taps use `NSClickGestureRecognizer` with `allowedTouchTypes = .direct`, which means Touch Bar touches.
- **`Preferences` / `DevPulsePreferencePane`** (`DevPulsePreferences.swift`): settings live in their own defaults suite, `com.st4rdhoom.devpulse`, because the widget runs inside Pock's process and `.standard` would be Pock's own preferences. The pane is registered through `PKWidgetPreferenceClass` in `Info.plist` and shows in Pock's Widgets Manager. Its UI is built in `loadView()`, because compiling a `.xib` needs Xcode's `ibtool`, so `nibName` is never loaded. Nothing pushes changes to the widget. It re-reads `Preferences` on each refresh: the view reads it on each draw and in `intrinsicContentSize`, and `refresh()` restarts the timer when the interval changes.
- **Intro** (in `DevPulseView`): when a meter gets its first non-nil reading (a fresh view after Pock launches, or after wake: `DevPulseWidget` observes `NSWorkspace.didWakeNotification` and `screensDidWakeNotification` (at most once per 5s, since a full wake fires both), calls `restartHistory()` to clear all histories, then refreshes), `push` fills that meter's whole history with it and records `intros[key]`. For `introDuration` (1.2s) the grid starts full: every dot above the reading is drawn lit and switches off at random. `sparkle(column:row:elapsed:)` gives each dot a random start in the first 75% and a fade over the rest, from the reading's colour to `unlitColor`. Lit dots stay lit throughout. CPU's first sample is nil, so its intro plays one refresh later. The redraw timer calls `updateAnimation` on every tick, so it slows down or stops once the intro ends.
- **Memory chips** (in `DevPulseView`): the memory meter has `chips = true`, so it draws only the current value, as a RAM stick, instead of a history graph. `chipColumns` splits the graph into 4 chips (an empty column, `nil`, between them), each split horizontally into two halves (an empty row between them), giving 8 sections of 1/8 of RAM each. Each column is a `[Bool?]` per row (lit, unlit, or gap). The bottom halves fill left to right, then the top halves, and each section fills bottom-up, row by row.
- **Memory animation** (in `DevPulseView`): `memoryBreath` is nil at normal pressure, 4s at warning and 1.5s at critical. Lit memory dots then dim to half alpha and back on a cosine curve (`Meter.breathPeriod`). `updateAnimation` runs one timer at the fastest rate any running animation needs (`timerInterval`). To trigger it: `memory_pressure -l warn` allocates real memory until macOS reports warning pressure; Ctrl-C frees it.
- **Battery animations** (in `DevPulseView`): `batteryAnimation` is `.charging` while `charging` and the newest battery column still has empty dots. macOS keeps reporting `IsCharging` while topping off at 100% ("finishing charge"), so a full column falls through to the next case. It's `.onAdapter` when plugged in but not charging, and `.none` otherwise. It's also `.none` when the battery meter is hidden or the view isn't in a window, so `viewDidMoveToWindow` stops the animation when the widget leaves the bar. A single `animationTimer` only triggers redraws, every 0.25s for charging and every 1/20s for on-adapter. The frames come from `systemUptime`, so the animation needs no state of its own. In charging mode, the empty dots in each battery column fill upward one row per step, and each column runs one step behind the column to its left. At 100% there are no empty dots, so nothing moves. In on-adapter mode, lit dots fade off (towards the meter's `unlitColor`) and back in 2×2 blocks, because single dots alone are invisible at small dot sizes, with single-dot fades layered on top (`max` of the two). `fade(column:row:time:)` takes block coordinates (`column / 2`, `row / 2`) and gives every block its own pseudo-random period (3–7s) and phase, with an eased sin² curve over 35% of each cycle. Under the fades, the base colour blends from `.systemGreen` towards `.systemBlue` and back on a cosine curve over `colorCycle` (10s). In this mode the battery meter has `showsValue = false`: the percentage is not drawn, and the width calculations leave out its slot, so the widget shrinks. Unlit dots use the meter's `unlitColor`: 20% white by default (not `.quaternaryLabelColor`, which disappears next to yellow), and a warm off-white at 50% (`memoryUnlitColor`) for memory.
